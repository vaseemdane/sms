# Implementation Gap Analysis: Zoho Workflow Blueprint vs. Existing Codebase

| Requirement | Existing implementation | Missing or defective behavior | Files/modules affected | Proposed change | Priority | Status |
|---|---|---|---|---|---|---|
| **Server-side auth & zero-trust token validation** | JWT Bearer token via `get_current_user` in `dependencies/auth.py` | `if raw_token.startswith("sms_jwt_"):` allows unsigned dummy tokens to bypass cryptographic signature verification. | `backend/app/dependencies/auth.py` | Remove dev token bypass; require valid signed JWTs with expiration checks. | Critical | Broken |
| **Authentication on internal modules** | Routers use `Depends(get_current_user)` | `GET /operations/lesson-notes` and `GET /materials/section/{section_id}` lack `current_user` dependency, exposing teacher notes and class materials unauthenticated. | `backend/app/api/v1/school_operations.py`, `backend/app/api/v1/materials.py` | Add `current_user = Depends(get_current_user)` and section membership verification. | Critical | Broken |
| **Dynamic Role-Based Access Control (RBAC)** | Dynamic `Role`, `Permission`, `RolePermission` models exist in DB and managed via `/super-admin/roles` | `PermissionChecker` only inspects static Python dict `ROLE_PERMISSIONS` and misses `admin` in `GRANULAR_ROLE_PERMS`. DB permissions are completely ignored at runtime. | `backend/app/core/permissions.py`, `backend/app/dependencies/auth.py` | Unify `PermissionChecker` to query DB `RolePermission` for `user.role_id` with memory/TTL cache and fallback to granular defaults. | High | Partially implemented |
| **Multi-Tenant / School Scope Enforcement** | `User`, `AdmissionBatch`, `IdGenerationSequence` have `school_id` | `Class`, `Section`, `StudentProfile`, `TeacherProfile`, `Exam` queries in `admin.py`, `principal.py`, `academics.py` do not filter by `current_user.school_id`. | `backend/app/api/v1/admin.py`, `academics.py`, `principal.py`, `attendance.py` | Inject tenant filtering (`school_id == current_user.school_id`) on all multi-tenant queries. | High | Partially implemented |
| **Parent BOLA Protection on Attendance** | `GET /api/v1/attendance/student` allows query by `student_id` | `elif current_user.user_type == "parent": pass` leaves `target_user_id` as `current_user.id` or ignores verification of `ParentChildLink`. | `backend/app/api/v1/attendance.py` | Validate `ParentChildLink` between `current_user.id` and target `student_id` (`403 Forbidden` if unverified). | Critical | Broken |
| **Parent BOLA Protection on Report Cards** | `GET /api/v1/students/report-card` accepts `student_id` parameter | Only allows `["super_admin", "admin", "teacher"]` to specify `student_id`. When called by parent, `student_id` is ignored and results in 404 for parent's user ID. | `backend/app/api/v1/students.py` | Allow `parent` to query `student_id` after verifying active `ParentChildLink`. | Critical | Broken |
| **Parent BOLA Protection on Consents & RSVPs** | `POST /operations/field-trips/{id}/consent` & `POST /operations/pta-meetings/{id}/rsvp` | Accepts arbitrary `student_id` without verifying that calling parent is linked to the student. | `backend/app/api/v1/school_operations.py` | Check `ParentChildLink` before saving consent or RSVP records. | Critical | Broken |
| **Draft vs. Published Separation on Grades** | `Exam.is_published` and `ExamMark.status` exist in DB | `GET /api/v1/students/report-card` joins `ExamMark` without filtering by `Exam.is_published == True` or `ExamMark.status == "PUBLISHED"`. | `backend/app/api/v1/students.py` | Enforce publication filter on gradebook queries for students and parents. | High | Broken |
| **Payment Status Validation** | Public admission application endpoint `POST /admissions/public/apply` | Directly accepts client `payload.paymentReference` and marks `app_fee_status = "PAID"` without server-side payment gateway verification. | `backend/app/api/v1/admissions.py` | Set initial status to `PENDING` until server-to-server webhook confirmation. | High | Broken |
| **Assignment Lifecycle Endpoints** | Models `Assignment`, `AssignmentTarget`, `AssignmentSubmission` exist in DB | `materials.py` only has `POST /materials` and `GET /materials/section/{id}`. Complete Assignment CRUD, student submission, and grading endpoints are missing from backend. | `backend/app/api/v1/materials.py` | Implement `POST /materials/assignments`, `GET /materials/assignments/section/{id}`, `POST /materials/assignments/{id}/submissions`, and `PATCH /materials/assignments/{id}/submissions/{sub_id}/grade`. | High | Missing |
| **Exam Moderation & Publication Workflow** | `ExamMark.status` has `DRAFT`, `SUBMITTED`, `PUBLISHED` states | No Principal moderation endpoint exists to approve or return marks for correction; no publication endpoint exists to publish report cards. Teachers can overwrite submitted marks. | `backend/app/api/v1/examinations.py`, `backend/app/models/exam.py` | Add `POST /examinations/{id}/moderate`, `POST /examinations/{id}/publish-results`, and enforce marks lock once submitted. | High | Missing |
| **Principal Dashboard Live Queries** | `principal.py` and `principal-dashboard.tsx` exist | `principal.py` hardcodes `today_str = "2026-10-24"` and returns static mock arrays for attendance, chronic absentees, and top performers. Frontend uses hardcoded charts. | `backend/app/api/v1/principal.py`, `school-ms/src/components/dashboard/principal-dashboard.tsx` | Replace mock arrays with live SQL aggregations (`func.count`, `func.avg`). Wire frontend to API. | High | Broken |
| **Parent Dashboard Ward Switching & Live State** | `parent-dashboard.tsx` has UI for children selector | Child list is hardcoded (`Rohan Sharma`, `Ananya Sharma`) and state is local dummy state rather than fetching from `/api/v1/parent/wards`. | `school-ms/src/components/dashboard/parent-dashboard.tsx` | Fetch verified wards from `/api/v1/parent/wards` and invalidate caches on child switch. | High | Broken |
| **Student Academics Navigation & Submission UI** | Next.js student routes exist for timetable and attendance | Sidebar lacks links to `/student/academics/materials` and assignments. Student submission flow is not accessible in navigation. | `school-ms/src/components/layout/sidebar.tsx`, `school-ms/src/app/(app)/student/` | Add navigation items and build submission pages. | Medium | Missing |
| **ParentChildLink Verification Fields** | `ParentChildLink` model in `student.py` has `parent_id`, `student_id` | Missing verification metadata: `relationship_type`, `verification_status`, `verified_by_user_id`, `access_start_date`, `access_end_date`. | `backend/app/models/student.py` | Add columns and update `get_current_parent_wards` dependency. | High | Partially implemented |
| **Frontend LocalStorage Persistence Reliance** | `sms-store.tsx` (2,339 lines) stores state in `edupulse_sms_clean_production_v5` | Client-side mutations do not consistently hit backend APIs for all operations; data lives in browser localStorage. | `school-ms/src/context/sms-store.tsx` | Bridge `sms-store.tsx` actions to async `apiClient` calls; eliminate fake localStorage fallbacks. | High | Partially implemented |
